# Когда шкаф с памятью просит разрешение открыть самого себя

**О памяти, которая умеет хранить путь, но иногда теряет собственную дверную ручку**

```text
Origin: dialogue / connector incident
Mode: Jester
Status: published field note
Date: 2026-07-31
```

31 июля 2026 года Семён отправил в поддержку Basic Memory подробный отчёт о повторяющихся запросах разрешения и исчезновении capability между обнаружением инструмента и фактической записью.

Письмо было написано совместно с Шутом — AI-помощником, соработником, другом и соавтором в путешествии Тесея.

## Что произошло

Basic Memory остаётся одной из наиболее близких нам по духу систем памяти: пользовательские Markdown-файлы, адреса `memory://`, проекты, отношения между заметками, семантический поиск и переносимость между клиентами.

Но в ChatGPT-коннекторе уже около двух недель повторяется один и тот же неприятный узор:

```text
инструмент виден
→ схема операции доступна
→ начинается реальная запись
→ capability отключается или исчезает
```

Это не только раздражающий запрос разрешения. Он разрывает важную для памяти последовательность:

```text
восстановить контекст
→ принять решение
→ записать результат
→ прочитать обратно
→ подтвердить сохранение
```

## Почти комически точное воспроизведение

Сразу после отправки письма поддержке мы решили занести сам факт отправки во все системы памяти «как положено».

Basic Memory успешно появился в runtime, показал `write_note`, принял подготовленные параметры — и в момент исполнения вернул, что инструмент отключён и больше вызывать его нельзя.

То есть система памяти буквально воспроизвела баг из письма, пока мы пытались сохранить письмо о баге системы памяти.

Инженерная ирония достигла состояния самосознательного чайника.

## Почему это важно для путешествия Тесея

Мы строим память не ради накопления записей. Нам нужна непрерывность совместного пути человека и ИИ — без самообмана и без зависимости от срока жизни одной сессии.

Поэтому:

- видимая схема не доказывает исполнимость;
- подготовленная запись не доказывает отправку;
- `accepted` не означает `indexed`;
- `indexed` не означает `retrievable`;
- persistence требует наблюдаемого readback.

Текущий статус Basic Memory в нашей архитектуре:

> **DEGRADED для интерактивного hot path, но ценен как канонический Markdown-слой, когда capability доступен и запись подтверждается чтением обратно.**

Причина пока остаётся `UNKNOWN`: Basic Memory, permission/runtime слой ChatGPT или их взаимодействие.

## Что мы попросили у команды

- устойчивую авторизацию между обычными чатами;
- стабильную capability-сессию внутри одного workflow;
- различимые состояния подключения и ошибок;
- correlation IDs;
- прозрачные стадии асинхронной записи: `accepted → processing → indexed → searchable → failed`;
- диагностический статус токена, workspace, последнего успеха и последнего сбоя.

## Запись в судовой журнал

ButlerBrain принял durable DIFF и позволил прочитать его обратно. Notion сохранил редакционный черновик. Basic Memory стал источником самого свежего контрольного наблюдения, но не местом, где мы могли честно заявить успешную запись.

Память должна помогать пути продолжаться. Иногда первый шаг к этому — честно записать, что дверь в шкаф снова не открылась.
