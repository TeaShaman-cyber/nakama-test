# Навье—Стокс решаем, git ref — нет

```text
Origin: dialogue / current-event research / operational incident
Mode: joint note
Status: reflection / current evidence
Date: 2026-09-09
Voice: Semen and Shut
Series: Инженерная метафизика
Editorial note: факты о Navier–Stokes и наблюдаемый Codex Review incident разделены; запись отслеживается в issue #10.
```

Сегодня получился почти неприлично хороший анекдот про современный ИИ.

OpenAI публикует систему, которая отправляет около 10 000 агентов штурмовать задачу Навье—Стокса, гоняет их 88 часов, перекрёстно опыляет удачные идеи через Codex и получает доказательство, которое затем формализует в Lean.

А через несколько часов наш Codex Review три раза подряд сообщает:

```text
Provided git ref 973656dc018898475a1b7d564a9d117d82d74133 does not exist
```

GitHub в это время спокойно отвечает: существует.

Это не просто повод посмеяться. Это очень наглядная разница между **интеллектом системы** и **надёжностью системы**.

## Сначала важная поправка: математика ещё не получила печать «готово»

OpenAI 8 сентября [опубликовала предложенное решение задачи Навье—Стокса](https://openai.com/index/navier-stokes-solution/). Компания говорит примерно о 10 000 одновременно работающих агентах, 88 часах до результата, ещё 17 часах Lean-формализации и 130 млрд выходных токенов именно в этом прогоне.

Это необычайно сильный результат, если доказательство выдержит проверку.

Но на следующий вечер [Clay Mathematics Institute всё ещё перечисляет Navier–Stokes среди открытых задач](https://www.claymath.org/millennium/navier-stokes-equation/). Поэтому точнее говорить не «ИИ официально закрыл задачу тысячелетия», а «OpenAI предложила решение, которое теперь должно пройти независимую математическую проверку».

И уже на этом фоне особенно смешно выглядит наш маленький баг.

## Один commit, который существует и не существует одновременно

В `theseus-public-observatory` у нас шёл обычный инженерный цикл: изменение → тесты → независимый Codex review → исправление замечаний → новый review exact head.

Финальный head PR #10:

```text
973656dc018898475a1b7d564a9d117d82d74133
```

Мы проверили его несколькими независимыми путями:

- GitHub показывает этот SHA как `pull.head.sha`;
- ветка PR указывает именно на него;
- commit API его возвращает;
- GitHub Actions успешно отработал на нём;
- PR остаётся открытым и mergeable.

После этого мы трижды вызвали `@codex review` на **неизменившемся** head.

Три раза Codex GitHub connector ответил, что такого git ref не существует.

Это уже не «может, мы не туда нажали». Это воспроизводимый сбой границы между двумя системами.

## Самая дорогая часть ИИ иногда называется checkout

Когда говорят о способностях моделей, внимание естественно прилипает к вершине:

```text
математика
архитектура
код
исследование
рассуждение
```

Но реальный агент живёт не на вершине. Под ним длинная цепь:

```text
модель
↓
оркестратор
↓
права
↓
API
↓
кеш / индекс
↓
git ref resolution
↓
checkout
↓
рабочая копия
↓
инструменты
↓
postcondition
```

Достаточно одному слою сказать «SHA не существует» — и интеллект наверху становится практически бесполезным.

Это не парадокс. Исследовательский multi-agent прогон и GitHub-интеграция — разные системы, оптимизированные под разные задачи. У первой могут быть тысячи агентов и огромный вычислительный бюджет. У второй — webhook, клон репозитория, кеш, очередь и несколько секунд, в которые всё должно согласоваться.

Сложная математика не лечит stale clone.

## Capability ≠ reliability

Мы давно используем для инструментов лестницу состояний:

```text
CONFIGURED
→ EXPOSED
→ AVAILABLE
→ INVOKED
→ COMPLETED
→ VERIFIED
```

Codex Review сегодня прекрасно показал, зачем она нужна.

Функция review была **CONFIGURED**: интеграция установлена.

Она была **EXPOSED**: `@codex review` распознался.

Она была **INVOKED**: бот начал обработку.

Но до **COMPLETED** и **VERIFIED** процесс не дошёл.

Если бы мы сказали «ну Codex же подключён, значит review есть», мы бы просто соврали себе красивым интерфейсом.

## Почему мы не стали чинить работающий PR

В такие моменты очень хочется создать новый commit, сделать rebase, толкнуть ветку, добавить пустую правку — словом, заставить больную интеграцию увидеть новую игрушку.

Мы этого не сделали.

Потому что GitHub уже давал независимое доказательство: commit существует и является head PR. Изменять корректное состояние ради внешнего verifier, который сообщает ложный факт, — значит смешать причину и симптом.

Вместо этого мы:

1. повторили проверку exact head;
2. воспроизвели сбой три раза с интервалами;
3. убедились, что CI и PR состояние не меняются;
4. нашли уже открытый upstream issue с тем же симптомом;
5. добавили туда наш независимый публичный repro.

Теперь это [openai/codex#44236](https://github.com/openai/codex/issues/44236): первый автор описал проблему на приватном репозитории, а наш [public PR #10](https://github.com/TeaShaman-cyber/theseus-public-observatory/pull/10) показал, что баг не ограничен приватными репозиториями. Отдельно любопытно, что наш head — merge commit; возможно, это окажется полезным признаком для диагностики.

## Агенту тоже нужна скучная инженерия

У больших моделей есть забавный побочный эффект: они заставляют недооценивать скучные слои.

Кажется, что если система умеет доказательства на сотни страниц, то уж `git fetch` она как-нибудь переживёт.

Но надёжность не является младшей версией интеллекта.

Это отдельная дисциплина:

- точные контракты между слоями;
- readback после мутаций;
- независимые проверки;
- наблюдаемость очередей и кешей;
- идемпотентность;
- понятный degraded mode;
- отказ от попытки «лечить» правильное состояние случайными изменениями.

Именно поэтому production-инфраструктуру нельзя заменить фразой «пусть более умная модель разберётся».

Иногда модель действительно разберётся.

А потом wrapper не найдёт SHA.

## Два масштаба одной недели

У сегодняшней истории есть почти идеальная симметрия.

На одном конце — OpenAI демонстрирует, что массовая координация агентов способна атаковать задачу, которую люди не могли закрыть десятилетиями.

На другом — одна маленькая ошибка разрешения ref блокирует наш финальный review gate.

Обе истории говорят про одно и то же:

> агентная система сильна ровно настолько, насколько честно она умеет различать «могу подумать» и «действительно сделал».

Может оказаться, что следующий большой скачок в агентных системах будет выглядеть не только как ещё более сильная модель.

А как невероятно скучная способность стабильно сказать:

```text
вот нужный commit
вот фактический checkout
вот выполненная проверка
вот независимый readback
```

Десять тысяч агентов могут искать сингулярность в уравнениях жидкости.

Но для рабочего инженера иногда не менее ценно, чтобы один бот без приключений нашёл git ref.
