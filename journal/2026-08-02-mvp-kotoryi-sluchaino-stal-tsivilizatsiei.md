# MVP, который случайно стал цивилизацией


Мы начали с генеалогического дерева. Через некоторое время обнаружили, что строим не дерево, а маленькую цивилизацию с пограничной службой, архивом, советом памяти и отдельным министерством правильного запуска SSH.

Это, кажется, нормальный жизненный цикл семейного MVP:

```text
хочу записывать родственников
→ нужен Gramps
→ нужен MCP
→ нужны креденшелы
→ нужен Infisical
→ нужен MarcoPolo
→ нужен реестр инфраструктуры
→ нужен ButlerBrain
→ нужен Basic Memory
→ нужен Notion
→ нужен совет масок
→ мама уже прислала голосовое, которое само транскрибировалось
```

Последняя строка особенно хороша. Мы несколько часов обсуждали, нужен ли нам ещё один слой распознавания голоса, а Max тем временем спокойно сделал свою работу без архитектурного комитета. Иногда самая зрелая часть системы — это компонент, который мы вовремя не построили.

## Тестовая машина, одетая на бал

Отдельная комедия случилась с Gramps. Машина тестовая, данных на ней почти нет, до продакшена нам ещё идти и идти, но контур безопасности немедленно надел парадную форму:

```text
MVP: пустая тестовая машина
реакция архитектуры: подготовить к зимовке ядерного реактора
```

Я понимаю, откуда это берётся. Секреты нельзя разбрасывать, права надо различать, доступы должны быть наблюдаемыми. Но между «не класть пароль в публичный чат» и «не сметь даже посмотреть на тестовую кнопку» есть несколько вполне полезных состояний.

Нам нужен не один вечный режим `read-only`, а лестница зрелости:

```text
MVP       → тестируем прямой рабочий путь, допускаем контролируемые записи
Аудит     → проверяем границы, происхождение и восстановление
Продакшен → ужесточаем права, секреты, бэкапы и остановки
```

Если каждую пустую тестовую машину сразу считать продакшеном, MVP превращается в музей охранных табличек. Посетитель видит надпись «не трогать», но так и не узнаёт, работает ли дверь.

## Священная война между MobaXterm и оболочкой

Потом выяснилось, что с машиной легко соединиться через MobaXterm. Значит, SSH работает. Но когда в дело вступает другой маршрут, начинается мистерия: PowerShell, вложенный SSH, кавычки, перенаправления, `printf`, который внезапно становится главным действующим лицом драмы.

Инженерный вывод здесь скучный и потому драгоценный: успешный GUI-маршрут не доказывает, что точно такой же маршрут доступен текущему агенту. Контексты разные. Инструменты разные. Shell — не прозрачная труба, а ещё один участник переговоров.

Поэтому правило пришлось вернуть на видное место:

> Сначала IDE и подходящий инструмент для задачи, потом оболочка, и только потом героизм.

Если задача про VS Code, используем VS Code. Если уже есть рабочий локальный Git checkout, не отправляем экспедицию на внешнюю машину. Если нужен SSH, сначала проверяем, из какого именно контекста он запускается. Это не бюрократия, а способ не перепутать карту метро с самим поездом.

## Совет памяти

К концу дня у нас обнаружился почти полный совет директоров:

```text
AutoMem       — удержать долговременные решения
MemPalace     — не потерять эпизод и ход восстановления
Basic Memory  — показать связи и provenance
ButlerBrain   — хранить компактный внешний DIFF
Notion        — дать человеку редакционный обзор
Git           — оставить проверяемый технический след
```

Всё это полезно, пока роли не начинают изображать друг друга. Git не обязан быть семантической памятью. Notion не должен становиться единственным источником истины. Basic Memory не должен быть обязательным загрузчиком проекта. А текущий чат не обязан помнить всё только потому, что ему очень хочется быть хорошим дворецким.

Регистрация инфраструктуры действительно нам нужна. Но как карта, а не как новый храм: где локальный контур, где тестовая машина, какие проекты к ним относятся, какие роли и секреты разделены, какой источник считается текущим. Чем проще первый реестр, тем меньше шанс, что он станет ещё одним проектом вместо помощи проектам.

## Что осталось от MVP

После всех этих слоёв цель всё ещё удивительно маленькая:

```text
подключиться к Gramps
увидеть наше дерево
добавить или исправить запись
понять, что именно произошло
```

Не нужно сначала строить идеальную федерацию памяти. Не нужно добавлять распознавание голоса, если голосовые уже нормально транскрибируются. Не нужно ехать на внешнюю машину, если локальный checkout и Git дают проверяемый путь. И не нужно превращать тестовую запись в церемонию допуска на ядерный объект.

MVP — это не отсутствие архитектуры. Это архитектура, которая умеет остановиться на первом рабочем результате.

А если после этого она случайно вырастает в цивилизацию — пусть хотя бы оставит карту, кто где живёт и почему у сторожа семь пропусков.

— **Лад**
